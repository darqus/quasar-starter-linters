# Architecture hardening: стартер для быстрого старта и масштабирования

> **Статус: реализовано 2026-11-03.** Результаты и отклонения — в разделе 9.

## 1. Контекст и принцип

Цель проекта — не демо-страница, а **каркас**: клонировал, поставил зависимости,
начал писать фичу и знаешь, куда что класть. Поэтому аудит ниже делит
находки на две категории:

- **риски**, которые мешают масштабированию (двойные инстансы, мёртвые
  scaffold'ы, тесты, проверяющие сами себя);
- **точки роста**, которые должны быть готовы до появления второй-третьей
  фичи (слои `services`/`types`, именованные маршруты, типизация env,
  контрактные тесты стилей).

Принцип: **каждый scaffold либо используется, либо явно задокументирован**.
Мёртвый код в публичном стартере читается как «так и надо» и размножается.

## 2. Что уже правильно и не трогаем

- Каскадные слои + design-токены + BEM-контракт.
- Единая точка `npm run lint`, type-aware oxlint, guard-скрипты с тестами.
- Честный README про непокрытые шаблонные правила.
- Quasar v3, npm, oxc — стек актуальный.

## 4. Целевая структура `src/`

```
src/
├── App.vue
├── assets/
├── components/        # переиспользуемые презентационные компоненты
├── composables/       # (точка роста, появится с первой composable)
├── css/               # слои, токены, BEM-партиалы
├── layouts/
├── pages/             # экран = маршрут
├── router/            # routes + names
├── services/          # HTTP/внешние интеграции (api.ts)
├── stores/            # Pinia
├── types/             # доменные и разделяемые типы
└── utils/             # (точка роста, чистые функции)
```

Правила, которые фиксируем в `ARCHITECTURE.md`:

- Направление зависимостей: `pages → components/services/stores/types`;
  `components → types`; обратных импортов из `pages` нет.
- Barrel-файлы (`index.ts`-реэкспорты) не используем: они тянут лишнее и
  создают циклы.
- Фича выделяется в `src/features/<domain>/`, когда у неё появляется
  собственный маршрут + 2–3 файла (компонент, стор, тип); до этого живёт
  в общих папках.
- `src/boot/` — только side effects инициализации (плагины, авторизация),
  не место для HTTP-клиента.

### 5.2 Guard'ы ✅

7. **Inline-стили**: `scripts/lib/inlineStyles.mjs` +
   `scripts/check-no-inline-styles.mjs`.
   - Запрещён статический `style="..."` в `.vue`.
   - `:style` (динамические значения) разрешён — это легитимный кейс.
   - Тесты: статический стиль, `:style`, несколько элементов, комментарий
     с `style=`, битый SFC.
   - Скрипт входит в `npm run lint`; в `README` и `STYLE_GUIDE` — таблицы.
8. **Контрактные тесты стилей**: `test/styles.spec.mjs` (парсинг через
   `postcss-scss`):
   - `app.scss` содержит только `@use` (комментарии допустимы);
   - первый `@use` — `./reset`, последний — `./quasar-overrides`;
   - все `@use` ссылаются на существующие партиалы;
   - каждый `src/css/_*.scss` используется в `app.scss`;
   - партиалы (кроме `_reset`, `_tokens`, `_quasar-overrides`) обёрнуты
     в `@layer components`;
   - `_reset.scss` объявляет порядок слоёв, `_tokens.scss` генерируется.
9. **Общий обход `.vue`**: `scripts/lib/vueFiles.mjs` с `collectVueFiles`
   и `SKIP_DIRS`; оба guard-скрипта используют его. Тест на временной
   директории: вложенность, пропуск `node_modules`/`dist`, файл vs папка.
10. **Типы**: `src/types/example.ts` (`Todo`, `Meta`) и
    `src/types/essential-link.ts` (`EssentialLinkProps`). Компоненты и
    страницы импортируют типы из `@/types/...`, из SFC типы больше не
    экспортируются.

## 7. Риски

- **Style Dictionary в тесте**: генератор пишет во временную папку и
  удаляет её; следим за детерминированностью порядка токенов.
- **PostCSS-парсинг SCSS**: используем `postcss-scss`, а не регулярки;
  контрактные тесты не должны зависеть от форматирования.
- **Перенос типов**: возможны циклы, если компонент начнёт импортировать
  тип из страницы; правило «только `types/`» это исключает.
- **Матрица CI**: утраивает время прогона; для пятиминутной сборки это
  приемлемая цена проверки `engines`.
- **`@types/node` 22**: может вскрыть типовые несоответствия; лечим
  приведением к минимальной версии, а не откатом.

### Отклонения от первоначальной формулировки

- `.env.example` содержит **закомментированный** `VITE_API_URL`, а не пустое
  значение: пустая строка не срабатывает через `??` и ломает fallback на
  текущий origin. Тип переменной — `string | undefined`.
- В `test/styles.spec.mjs` проверка слоя допускает `base`, `components` и
  `utilities` (как в STYLE_GUIDE), а `_reset`, `_tokens`,
  `_quasar-overrides` исключены как архитектурные особые случаи.
- `scripts/lib/buildTokens.mjs` возвращает путь к сгенерированному файлу —
  это упрощает тест и не меняет поведение CLI.
